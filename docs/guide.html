Capacitance Dilatometry Processor
for Quantum Design PPMS® systems — offline install & user guide

This guide covers installing the processor on offline / corporate Windows and macOS machines under several environments, and walks through every user workflow: GUI reduction, headless batch runs, the interactive quality-control (QC) window, multi-angle (rotation) series, and building a calibration for your own dilatometer cell.

2. Installation

2a. Windows, no Python installed (fully offline)

  1. Run python_installers\python-3.12.10-amd64.exe.
  2. On the first screen tick “Add python.exe to PATH”, then “Install Now”.
  3. Open Command Prompt, cd into this folder, and install the dependencies from the local wheels (no network is used): 
    py -3.12 -m pip install --no-index --find-links wheels\win_amd64 -r app\scripts\requirements.txt
  4. Start the app: 
    py -3.12 app\scripts\dilat_app.py

If your user account cannot install software, choose “Customize installation” → untick “Install for all users”; the per-user install needs no admin rights.

2b. macOS, no Python installed (fully offline)

  1. Run python_installers/python-3.12.10-macos11.pkg (double-click, follow the installer). It installs python3.12 with tkinter.
  2. Open Terminal, cd into this folder: 
    python3.12 -m pip install --no-index --find-links wheels/macos_arm64 -r app/scripts/requirements.txt
python3.12 app/scripts/dilat_app.py
Intel Macs: the bundled wheels are Apple-silicon only. On an Intel Mac use conda (2c), or prepare a macosx_x86_64 wheel folder on any online machine: pip download -r app/scripts/requirements.txt --only-binary=:all: --platform macosx_10_13_x86_64 --python-version 3.12 -d wheels/macos_x86_64.

2c. Machine with conda / Anaconda (typical corporate setup)

If conda can reach its channels (directly or via a corporate proxy/mirror):

conda env create -f environment.yml
conda activate dilatometry
python app/scripts/dilat_app.py

If conda is fully offline, let conda provide only the interpreter (3.12 is usually cached or on the corporate mirror) and install the science stack from the bundled wheels:

conda create -n dilatometry python=3.12
conda activate dilatometry
pip install --no-index --find-links wheels/win_amd64 -r app/scripts/requirements.txt

(wheels/macos_arm64 on a Mac.) Conda’s Python already includes tkinter.

2d. Machine that already has Python 3.12

Keep the install isolated in a virtual environment:

# Windows
py -3.12 -m venv dilat-env
dilat-env\Scripts\activate
pip install --no-index --find-links wheels\win_amd64 -r app\scripts\requirements.txt

# macOS
python3.12 -m venv dilat-env
source dilat-env/bin/activate
pip install --no-index --find-links wheels/macos_arm64 -r app/scripts/requirements.txt
A Python built by Homebrew/pyenv may lack tkinter (python3.12 -m tkinter opens a test window if it is present). The python.org and conda interpreters always have it.

2e. Check the install

python -c "import numpy, pandas, scipy, matplotlib, tkinter; print('all good')"

Then python app/scripts/dilat_app.py — a window titled “Dilatometry Processor” must open, showing “No file selected — Browse…” at the Run button.

3. How the processor works (2 minutes)

Raw input is a PPMS .dat export (tab-delimited; a comma-separated *_all.csv archive of the same columns is also accepted — its pre-computed columns are ignored and everything is recomputed from the raw T, C [pF], δl columns). The pipeline:

  1. Separate the record into temperature sweeps and field (magnetostriction) loops.
  2. Subtract the empty-cell background from calibrations.json — branch-aware: cooling segments get the cooling calibration, warming segments the warming one.
  3. Compute ΔL/L₀ referenced to the lowest temperature (Küchler RSI 2016, Eq. 6), plus α(T) and λ(B) per loop.
  4. Gate the result (glitch scan, paramagnetic-α sign, cool/warm consistency…) and write CSV + PNG + a _provenance.json that records every decision.
The shipped calibrations.json is an example from the authors’ cells. Quantitative results for your own dilatometer require your own empty-cell calibration — see Workflow 5.

4. Workflow 1 — GUI: reduce one run and inspect it

Step 1 — open a file. Browse… (or Cmd/Ctrl-O) and pick a raw .dat or a *_all.csv archive.

Step 2 — detect the cell. The app fits the plate constant from the file’s (C, δl) pairs and pre-selects standard/stress cell or mini cell. Check the suggestion; you can override it. Enter the sample thickness L₀ (mm) — the “Run will use:” line under the Run button always states exactly what the next run will do (note: batch Run reads L₀ from the reducer’s configuration, not from this field; the field is honored when opening QC).

Output resolution (optional). Two fields on the parameter row control how many points land in the exported figures and CSVs, and they are applied to the batch Run:

  • α bin (K) — the α(T) coefficient is computed in temperature bins; this is the bin width. Smaller → more α points but noisier; larger → fewer, smoother. Default 3 K. (α is a derivative, so it is always binned — that is why _alpha.csv has far fewer rows than _Tdep_clean.csv.)
  • ΔL/L₀ spacing (K) — thin the thermal-expansion output to roughly one point per this many kelvin. Leave blank to keep every point (full resolution, the default); set e.g. 2 or 5 to get a lighter figure and a smaller CSV.

Step 3 — Run. Standard/stress cell: reduces the selected file. Mini cell: reduces the whole angle series described by the angle_runs.json in the data folder (the app asks for confirmation first, since this sweeps the folder).

Step 4 — results table. Each reduced run appears with a status: PASS = quality gates met · CHECK = a gate failed, inspect in QC · PRELIM = mini run, gates advisory · ERR = unreadable. Select a row and press Open QC to inspect it interactively (Workflow 4).

5. Workflow 2 — headless str-cell reduction

python app/scripts/reduce_str_batch.py \
    --data /path/to/folder --file myrun.dat \
    --L0 0.058 --transition 177
OptionMeaning
--data, --fileFolder and filename of the raw run.
--L0Sample thickness along the measurement axis, in cm.
--transitionOptional transition temperature (K): drawn on figures and used to split the magnetostriction panels into below/above-transition.

The console prints each gate (GATE … PASS/FAIL); the exit code is non-zero when an enforced gate fails, so the reducer can sit in shell scripts. Outputs are named after the input file: Output/str/<stem>_Tdep_clean.csv, …_Bdep_clean.csv, …_alpha.csv, PNGs, and …_provenance.json.

6. Workflow 3 — mini-cell rotation series

Describe the series once in an angle_runs.json placed in the data folder (or passed via --runs):

{"stem": "MYSAMPLE_mini",
 "L0_cm": 0.02,
 "transition_K": 100.0,
 "runs": [
   {"angle_deg": 0,   "tag": "rot0",    "glob": "*rot0*.dat"},
   {"angle_deg": 45,  "tag": "plus45",  "glob": "*plus45*.dat"},
   {"angle_deg": 90,  "tag": "plus90",  "glob": "*plus90*.dat"},
   {"angle_deg": -45, "tag": "minus45", "glob": "*minus45*.dat", "rescale": 1.0}
 ]}
KeyMeaning
stemPrefix of all output filenames.
L0_cmSample thickness (cm), applies to every angle.
transition_KOptional transition line on the figures.
runs[].globFilename pattern matching exactly one file per angle.
runs[].rescaleOptional raw-δl factor for a run converted with the wrong plate radius (Workflow 6). Omit otherwise.
python app/scripts/reduce_mini_batch.py --data /path/to/folder

Per-angle outputs (like Workflow 2) plus, with ≥2 angles, a combined temperature-dependence overlay, and with ≥3 angles, polar anisotropy figures (ΔL/L₀ and λ(Bmax) vs angle, 2-fold mirrored — colliding mirror nodes are averaged and the disagreement printed to the console as a symmetry check).

Mini runs are never step-stitched. Jump-and-recovery staircases below a magnetic transition can be domain-avalanche / remanence signal; stitching would rectify them into fake drift. This is deliberate and not configurable from the command line.

7. Workflow 4 — the interactive QC window

python app/scripts/qc_str_cell.py  --data /path/to/folder --file myrun.dat --thickness 0.058
python app/scripts/qc_mini_cell.py --data /path/to/folder --glob "*mini*.dat" --thickness 0.02

(or simply Open QC on a results row in the GUI). The window shows every separated curve of the run with per-curve controls:

ControlWhat it does
Curve selector (right panel)Pick a curve; with many curves the list scrolls — the mouse wheel scrolls it, the counter shows e.g. “5–16 / 18”.
Curve: on/OFFInclude or exclude the selected curve from the export.
View: clean/RAWToggle between cleaned data and the raw points behind them.
Legend: on/offShow/hide the legend.
Trim slidersCut settling tails at either end of the selected curve.
Smooth sliderRolling-median window for the displayed curve.
Drop δl below [1e-6 cm]Threshold filter on raw δl (plate-touch spikes).
Save / exportWrites the cleaned CSVs + figures with your selections applied.

Everything you exclude or trim is recorded, so an exported dataset remains auditable.

8. Workflow 5 — calibrate your own cell

You need one or more empty-cell runs with a Cu (copper) sample of known thickness, covering the temperature range you measure in, ideally both cooling and warming at the same rates you use for samples.

  1. Put the Cu run(s) where the builder can see them and run: 
    python app/scripts/cu_calibration_builder.py --help
    The builder segments each run into cooling/warming branches, repairs instrumental steps, fits polynomial backgrounds per branch, decomposes them into the Küchler Eq.-(7) length model (so a background can be virtualized at your actual sample thickness), and runs internal round-trip gates before writing calibrations.json.
  2. Replace app/scripts/calibrations.json with your registry.
  3. Reduce a Cu run as if it were a sample — the result should be flat at the 10⁻⁵ level. That is your end-to-end check.

Per-branch overrides (exclude a glitchy window, drop a branch) go into calibration_config.json — the file documents its own format.

9. Workflow 6 — wrong plate radius? (plate-constant audit)

PPMS converts capacitance to δl with a configured plate radius. If a run was recorded with the wrong one (e.g. the 7 mm default instead of a mini cell’s 5 mm), its δl is scaled by a constant factor. To detect this, list your files in FILES at the top of app/scripts/plate_constant_audit.py and run it: it inverts the Pott–Schefzyk gap relation per file and prints the implied plate radius. r ≈ 7 mm on a mini-cell run means wrong conversion — fix it by setting that run’s "rescale" in angle_runs.json to K_correct / K_fitted (the ratio the audit prints).

10. Understanding the outputs

FileContents
*_Tdep_clean.csvThermal expansion: T, B, ΔL/L₀, branch (cool/warm), curve label. Header lines starting with # carry the provenance — read with pandas.read_csv(path, comment='#').
*_Bdep_clean.csvMagnetostriction loops: λ(B) per loop temperature; str runs carry both the stitched column and lambda_raw_dL_L0 (unstitched) so every correction is reversible.
*_alpha.csvLinear expansion coefficient α(T) (binned derivative).
*_provenance.jsonThe full decision record: source file, L₀ and its source, calibration records used per branch, gate results, excluded rows, per-loop stitch lists. Read this first when a result surprises you.

Units: T in K; B in T; raw δl in 10⁻⁶ cm; L₀ in cm in code (mm in the GUI); ΔL/L₀ dimensionless (figures ×10⁻³); α in 10⁻⁶ K⁻¹.

11. Troubleshooting

SymptomCause / fix
pip … no matching distribution during offline installPython version is not 3.12, or wrong wheels folder for the OS/CPU. Check python --version and the --find-links path.
ModuleNotFoundError: _tkinterThe interpreter was built without Tk (common for Homebrew/pyenv). Use the bundled python.org installer or conda.
GUI opens but Run is greyed outNo file selected — use Browse… The “Run will use:” line explains the current state.
Can’t see the Results table / Open QC / Plot pre-cleanup buttonsOn a small or display-scaled screen the window is taller than the screen. The whole form scrolls — use the scrollbar on the right or the mouse wheel to reach the lower sections, or drag the window taller. (The window also opens no taller than your screen.)
PermissionError … Output/…pngThe app couldn’t write results inside its own folder (read-only or policy-locked install, e.g. a managed Mac blocking ~/Downloads). Results now go to a dilat_output/ folder next to your data file by default; the log prints “Output → …”. If even that is blocked they fall back to ~/dilatometry_output. Put your data somewhere you can write, or move the app out of a locked folder.
no recognizable PPMS dilatometry columnsThe file is not a PPMS export (needs T PPMS [K], C [pF], delta l [1E-6 cm]). Wrong file, or wrong export mode in the PPMS software.
no angle-run spec from the mini reducerCreate an angle_runs.json in the data folder (Workflow 3).
pattern … matched [] or matched several filesThe glob of that angle must match exactly one file — make it more/less specific.
Gate paramagnetic alpha … FAILα is negative where it should be flat/positive: usually a wrong L₀, a wrong calibration record, or a wrongly-converted run (Workflow 6). Check the provenance JSON.
Polar figures missingThey need ≥3 angles sharing a temperature window; the console says so explicitly.
Results look shifted between cooling and warmingExpected at the 10⁻⁴ level (cell hysteresis) — the calibration is branch-aware, but a single-branch calibration registry cannot correct the other branch. Record both branches when calibrating.
